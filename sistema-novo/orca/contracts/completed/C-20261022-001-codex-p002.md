# Aditivo A1 (2026-10-22) — escopo P002–P006 e fluxo de PR/revisão

Decisão do usuário: o programador segue as tarefas **em ordem**, fase por fase, até o fim, e conduz a revisão diretamente com o testador.

## Escopo ampliado
Ordem obrigatória (respeitando `depends_on`):
P002 (T010–T015) → P003 (T020–T022) → P004 (T030–T032) → P005 (T040–T043) → P006 (T051, T052, depois T044 E2E).
T050 já foi concluída pelo Chief. Antes de cada fase, leia o `PHASE.md` e as tarefas dela; as regras novas de R12 (ADR-011: contas inativas não transferem) valem a partir da T013.
Dependências externas autorizadas: `modernc.org/sqlite` (P003), `github.com/cucumber/godog` (P004); no frontend: react, react-dom, vite, @vitejs/plugin-react, vitest, @testing-library/react, @testing-library/user-event, @testing-library/jest-dom, jsdom, msw; E2E: @playwright/test. Qualquer outra → ORCA/ESCALATE.

## Autoridade ampliada
- may_modify: `sistemabancariorefatorado/**` exceto `docs/` e `README.md` (do agy-doc); arquivos de tarefa das fases P002–P006 (só `status` e "Evidência de conclusão"); seus diários em `.orca/phases/<fase>/diaries/`.
- Pode abrir Pull Requests com `gh pr create`. **Não** faz merge em `main` (é do Chief).

## Fluxo por fase (um "pull grande" = um PR por fase)
1. Atualize `main` (`git checkout main && git pull`) e crie `codex/p00N-<nome-da-fase>`.
2. Execute as tarefas em ordem com TDD (commits RED/GREEN/REFACTOR), push frequente.
3. Ao terminar a fase: `gh pr create --base main --head codex/p00N-... --title \"P00N: <título>\" --body \"<tarefas, como testar, evidências>\"`; tarefas com `status: review`.
4. **Peça a revisão você mesmo** ao agy: `ORCA/REVIEW_REQUEST | C-20261022-002 | P00N | PR #<n> <url> | branch <b> | tarefas <..> | como testar: <comandos>`.
5. Ao receber `ORCA/REVIEW_RESULT`, **avalie cada observação**: aceite (corrija com commit referenciando o achado) ou recuse com justificativa técnica. Registre no diário e responda ao agy com `ORCA/REVIEW_RESPONSE | PR #<n> | aceitas: <ids> | recusadas: <id: motivo> | commits: <hashes>`.
6. Se você corrigiu algum achado **bloqueante**, peça nova rodada (máx. 2 rodadas por PR; depois disso, ORCA/ESCALATE ao Chief).
7. Rodada encerrada → `ORCA/DONE | P00N | PR #<n> | testes: <saída resumida de go test/npm test>` para `run:run_632b4c0e3c2c`. Aguarde a mensagem `ORCA/GO P00N+1` do Chief (ele faz o merge e libera a próxima fase).
