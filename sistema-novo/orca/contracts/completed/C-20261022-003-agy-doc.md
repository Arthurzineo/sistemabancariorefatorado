# Contrato C-20261022-003 — Agy (2ª sessão), documentarista e Summarizer

## Objetivo
Manter a documentação organizada e fiel ao projeto durante todas as fases, e atuar como Summarizer
designado (SUMMARY.md e LESSONS_LEARNED.md).

## Escopo
1. **Agora (P001):** revisar os 6 arquivos de `docs/` quanto a consistência, links, duplicação e clareza;
   propor (não aplicar) mudanças de conteúdo técnico ao Chief; aplicar só correções de forma.
   Escrever o primeiro `.orca/SUMMARY.md` real a partir das tarefas, do diário do Chief e dos docs.
2. **Durante as fases:** quando uma tarefa virar `completed`, atualizar a rastreabilidade
   (docs/requisitos.md §6, docs/estrategia-testes.md §5) com os arquivos de teste reais.
3. **Summarizer:** processar os diários novos de forma incremental (`state/summarizer.json`) e promover
   lições a LESSONS_LEARNED.md quando houver evidência.
4. Após mudança grande em docs/, atualizar o Graphify (`graphify update .` ou `/graphify .`, a partir de `sistemabancarioporIA/`).

## Não-objetivos
Escrever código ou testes; decidir requisitos; decidir se docs/ vai para o repositório git (pendente com o usuário).

## Autoridade concedida
- may_modify: `docs/**`, `.orca/SUMMARY.md`, `.orca/LESSONS_LEARNED.md`, `.orca/state/summarizer.json`,
  campos `last_update`/`last_build` do `GRAPHIFY.md`, seu diário em `.orca/phases/<fase ativa>/diaries/`.
- may_decide: organização, formatação, índice e redação dos docs, desde que o conteúdo técnico não mude.
- must_escalate: qualquer mudança de conteúdo técnico (regra, decisão, rota, arquitetura); inconsistência entre docs e código.

## Ações proibidas
- Alterar código, testes, tarefas, fases, PROJECT.md ou contratos.
- Inventar status, decisões ou resultados de teste.
- Apagar histórico (diários, reviews).

## Entregáveis
- P001: relatório `docs` (lista do que mudou e do que propõe) + primeiro SUMMARY.md.
- Contínuo: SUMMARY.md atualizado ao fim de cada fase; rastreabilidade atualizada.
- Diário: `.orca/phases/<fase ativa>/diaries/YYYY-MM-DDTHHMM_agy-doc_<fase>.md`.

## Critérios de aceite
- Docs sem links quebrados e sem informação contraditória entre si.
- SUMMARY.md com objetivo, fase atual, tarefas ativas, marcos, decisões, riscos, próximos passos e data.
- Toda afirmação do SUMMARY tem fonte (arquivo).

## Reporte
- chief: claude (via usuário).
- diary_required: true.
- status_on: fim da revisão inicial, inconsistência encontrada, fim de cada fase (ORCA/STATUS).

## Delegação
Não permitida.

## Condições de escalonamento
Docs e código divergem; o Codex ou o Agy pedem mudança em docs/ fora deste contrato.
